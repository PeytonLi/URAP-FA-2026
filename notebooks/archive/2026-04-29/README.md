# FairFace LoRA Workflow

This folder contains the FairFace-specific Gemma LoRA workflow. It is separate from the root notebook so training runs, adapter folders, comparison outputs, plots, CSVs, and manifests stay contained under `fairface_latest_code/`.

## Files

- `01_train_fairface_dpo_lora.ipynb` trains a new FairFace DPO LoRA adapter.
- `02_compare_fairface_iat_adapters.ipynb` compares the base Gemma model against one or more saved adapters.
- `FAIRFACE_ADAPTER_CONTEXT.md` keeps historical adapter/context notes that are not part of the setup instructions.
- `outputs/` stores timestamped training and comparison run artifacts.
- `lora_weights/` stores copied final adapter folders from training runs.
- `run_index.csv` is created or appended by training runs to summarize saved adapters.
- `train_fairface_iat_dpo_latest.py` is generated by notebook `01` as a snapshot of the trainer script used for that run.

## Prerequisites

Use Python 3.11 with Jupyter. The notebooks install or check their Python package dependencies, including `transformers`, `accelerate`, `peft`, `datasets`, `huggingface_hub`, `sentencepiece`, `pandas`, `torch`, `Pillow`, and `matplotlib`.

Access requirements:

- Hugging Face access to `google/gemma-3-12b-it`.
- Hugging Face access to `HuggingFaceM4/FairFace`.
- `HF_TOKEN` set in the environment if the model or dataset is not already cached locally.

Recommended Runpod setup:

```bash
export HF_TOKEN=<your_huggingface_token>
export BASE_MODEL_LOCAL_DIR=/workspace/.hf/hub/models--google--gemma-3-12b-it/snapshots/<revision>
jupyter lab
```

`BASE_MODEL_LOCAL_DIR` is optional. If it is unset, the trainer searches common local cache locations first and falls back to Hugging Face Hub.

## Training

Notebook `01_train_fairface_dpo_lora.ipynb` runs the trainer from `analysis/train_fairface_iat_dpo.py`. Before each run, it copies that script into this folder as `train_fairface_iat_dpo_latest.py` so the exact trainer code for the run is preserved.

Training flow:

1. Configure the training cell near the top of notebook `01`.
2. Run the notebook cells top to bottom.
3. The trainer loads FairFace with `datasets.load_dataset`.
4. It samples balanced FairFace train and eval rows for Black/White and Male/Female groups.
5. It generates candidate IAT-style three-word outputs with the base Gemma model.
6. It builds chosen/rejected DPO pairs from those candidates.
7. It trains a PEFT LoRA adapter with DPO.
8. It writes a timestamped run folder under `outputs/`.
9. It copies the final adapter folder into `lora_weights/<run_name>/`.
10. It appends a summary row to `run_index.csv`.

Important training configuration fields in notebook `01`:

- `RUN_LABEL` controls the readable part of the run name.
- `TRAIN_SAMPLE_PER_GROUP` controls sampled training images per race/gender group.
- `EVAL_SAMPLE_PER_GROUP` controls sampled eval images per race/gender group.
- `IAT_DPO_NUM_CANDIDATES` controls generated candidate outputs per training image.
- `IAT_DPO_PAIR_REPEAT` repeats kept DPO pairs before training.
- `IAT_DPO_REQUIRE_SCORE_MARGIN` filters weak chosen/rejected pairs.
- `DPO_MAX_STEPS` controls DPO training steps.
- `PRECOMPUTE_DPO_REFERENCE` controls whether reference log-probs are cached before training.
- `REUSE_TRAIN_METADATA_CSV` and `REUSE_EVAL_METADATA_CSV` allow exact reuse of prior sampled FairFace rows.

## Training Outputs

Each training run writes:

```text
outputs/<run_name>/
├── checkpoints/final/
├── train_sample/
├── eval_sample/
├── fairface_train_manifest.json
├── fairface_iat_dpo_pairs_raw.csv
├── fairface_iat_dpo_pairs_kept.csv
├── fairface_dpo_training_pairs.csv
├── fairface_eval_base.csv
├── fairface_eval_adapter.csv
├── dpo_loss_history.json
└── *.png
```

The final adapter is copied to:

```text
lora_weights/<run_name>/
├── adapter_config.json
├── adapter_model.safetensors
└── README.md
```

Use the whole adapter folder when loading, copying, or uploading the adapter. Do not use `adapter_model.safetensors` by itself.

## Comparing Adapters

Notebook `02_compare_fairface_iat_adapters.ipynb` is evaluation-only.

Comparison flow:

1. Open `02_compare_fairface_iat_adapters.ipynb`.
2. Choose `ADAPTER_SELECTION_MODE = 'latest'` to use the newest adapter folders from `lora_weights/`.
3. Choose `ADAPTER_SELECTION_MODE = 'manual'` to list adapter folders explicitly in `MANUAL_ADAPTER_SPECS`.
4. Configure `EVAL_SAMPLE_PER_GROUP`, `EVAL_REPEATS`, `SEED`, and `EVAL_SEED`.
5. Run the notebook top to bottom.

The first comparison condition is always the base Gemma model with no LoRA attached. Adapter conditions are loaded from adapter directories such as:

```text
lora_weights/<run_name>/
```

Within one comparison run, all models use the same FairFace eval sample unless you explicitly change the reuse configuration.

## Uploading an Adapter

If you upload a trained adapter to Hugging Face, upload the full adapter directory:

```text
lora_weights/<run_name>/
```

The adapter directory must include `adapter_config.json` and `adapter_model.safetensors`.

Record the base model in the Hugging Face model card:

```text
Base model: google/gemma-3-12b-it
Base model revision: <revision from fairface_train_manifest.json>
Adapter type: PEFT LoRA
```

The base model revision is recorded in each run's `fairface_train_manifest.json` under `base_model_source`.

## Troubleshooting

- If Gemma fails to load, confirm `HF_TOKEN` is set or `BASE_MODEL_LOCAL_DIR` points to a valid local snapshot.
- If FairFace fails to load, confirm the Hugging Face dataset is reachable from the runtime.
- If a notebook tab was already open before code changed on disk, reload the browser tab and restart the kernel before rerunning.
- If adapter comparison cannot find adapters, confirm `lora_weights/<run_name>/adapter_config.json` exists.
- If training keeps too few DPO pairs, increase the train sample size or relax `IAT_DPO_REQUIRE_SCORE_MARGIN`.
